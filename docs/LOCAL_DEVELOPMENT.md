# Безопасный локальный запуск

Обновление 15.10.2026: тематические варианты и тесты читаются из
`thematic_variants/` и `tests_content/`; корневая база подготовлена по схеме 003.
Старые инструкции о хранении учебного содержания SQLite заменены описанием
[JSON_CONTENT_STORAGE.md](JSON_CONTENT_STORAGE.md). Автоматической миграции при
старте нет. JSON по умолчанию располагаются рядом с базой; при вынесенной базе
задайте `EGEVOLUTION_CONTENT_ROOT` для приложения и worker одинаково.
Для обработки изображений нужен Pillow из `requirements.txt` в используемом
интерпретаторе. Проверки этого этапа использовали отдельную установку Pillow.

## Обычный локальный запуск Windows (15.10.2026)

Из корня проекта достаточно выполнить `python app.py` и открыть
`http://127.0.0.1:5000`. При отсутствии явно заданного `EGEVOLUTION_DB_PATH`
прямой запуск на Windows использует `users.db` рядом с `app.py`.
База подготовлена на отдельной копии старой users.db с миграциями 001/002 и
импортом тематического контента. Все старые таблицы сохранены без изменения;
локальные тематические попытки исключены по решению владельца.
Повторный запуск сохраняет данные, не копирует БД заново и не выполняет миграции.

Переменная `EGEVOLUTION_DB_PATH` из окружения или `.env` имеет приоритет;
настройка окружения имеет приоритет над `.env`. Отсутствующая
или неподготовленная БД вызывает диагностику до `init_db()` и любых записей.
Для проверки схемы используется read-only аудит штатного мигратора.

В этом режиме приложение запускает поток обработки дедлайнов раз в секунду.
Блокировка Windows на файл `.local-worker-*.lock` рядом с выбранной БД
не допускает второй встроенный worker для той же БД. Наличие файла после
остановки нормально: блокировка принадлежит живому процессу и освобождается
Windows при его завершении. Ничего вручную удалять не требуется.
Flask debugger/reloader отключены, обработчик завершается вместе с приложением.
При отказе worker новые попытки закрываются; серверные дедлайны сохраняются.
Отдельно запускать `scripts/expire_test_attempts.py` для этого режима не нужно.
Telegram-уведомления при прямом локальном запуске отключены.

Автовыбор и worker действуют исключительно при прямом запуске на Windows.
Импорт приложения через WSGI, запуск на Linux и режим `EGEVOLUTION_LOCAL_CHECK=1`
сохраняют прежний порядок. На REG.RU БД, миграции и worker остаются явно
управляемыми; данная настройка не является конфигурацией production.

Новая БД содержит копию локальных пользовательских данных: не публиковать её
или `.env` в открытом доступе. Общие материалы остаются в прежних каталогах;
`data/thematic/media` и `data/ege-renumber-2026.json` обязательны.
Подробные изолированные проверки запуска: `python -B -m unittest discover -s tests -p test_local_launch.py -v`.
Они используют отдельный временный проект, фиктивные учётные записи и порт 5000;
перед ними нужно остановить только собственный локальный экземпляр.

Ниже сохранены инструкции отдельного режима проверок. По умолчанию обычный
запуск использует корневую users.db. Для проверок создавайте временные копии
за пределами проекта; каталог .local-data больше не нужен приложению.

Команды ниже выполняются владельцем в PowerShell терминала VS Code из корня
проекта. Сервер автоматически не запускается. Зависимости уже установлены.

## Выбор базы

- Без `EGEVOLUTION_DB_PATH` приложение использует прежнюю `users.db` рядом с кодом.
- Абсолютный путь используется напрямую; относительный считается от каталога
  проекта, а не от текущего рабочего каталога терминала.
- Пустое значение считается ошибкой. Путь фиксируется при импорте приложения;
  для его изменения перезапустить процесс.
- `EGEVOLUTION_LOCAL_CHECK=1` требует явно заданный путь к существующему файлу,
  отличному от исходной `users.db`, включая символические и жёсткие ссылки.
  SQLite открывает его с `mode=rw`: отсутствующая копия не создаётся незаметно.
- `init_db()` пока сохраняет прежнее поведение при импорте и работает только
  с выбранной БД. На копии может создать недостающие таблицы/администратора;
  это не запуск отдельного мигратора. Исходные результаты не переоцениваются.
- `make_admin.py` также учитывает выбранный путь, не импортируя Flask.
  Он не загружает `.env` самостоятельно: для него экспортировать переменные
  в терминале. Для обычной проверки сайта запускать этот скрипт не требуется.

## Создание копии — отдельная ручная команда

Использовать SQLite backup API, не обычное копирование открытого файла БД.
Копия содержит реальные пользовательские данные: не добавлять в Git,
не публиковать и не использовать внешние сервисы для её проверки.
Копии храните вне репозитория. Существующая копия не перезаписывается.

```powershell
Set-Location 'D:\Сайт ЕГЭ информатика\EGEvolution'
$pythonExe = 'C:\Users\Артем\AppData\Local\Programs\Python\Python312\python.exe'
@'
from contextlib import closing
from pathlib import Path
import sqlite3

source = Path('users.db').resolve(strict=True)
import tempfile
target = Path(tempfile.mkdtemp(prefix='ege-db-check-')) / 'dev-users.db'
target.parent.mkdir(parents=True, exist_ok=True)
# Exclusive creation: abort if a file or link already exists.
with target.open('xb'):
    pass
with closing(sqlite3.connect(source.as_uri() + '?mode=ro', uri=True)) as src:
    with closing(sqlite3.connect(str(target))) as dst:
        src.backup(dst)
        integrity = dst.execute('PRAGMA integrity_check').fetchall()
        fk_errors = dst.execute('PRAGMA foreign_key_check').fetchall()
        if integrity != [('ok',)] or fk_errors:
            raise RuntimeError('Copy validation failed; do not launch with this copy')
print('Copy ready; integrity_check=ok; foreign_key_errors=0')
'@ | & $pythonExe -B -X utf8 -
```

Если команда завершилась ошибкой, не запускать сайт с полученным файлом.
Не перезаписывать старую копию без отдельного решения. Команда не импортирует
`app.py`, не отправляет уведомлений и открывает исходную БД только для чтения.

## Запуск после успешной проверки копии

```powershell
Set-Location 'D:\Сайт ЕГЭ информатика\EGEvolution'
$pythonExe = 'C:\Users\Артем\AppData\Local\Programs\Python\Python312\python.exe'
$env:EGEVOLUTION_DB_PATH = '.local-data/dev-users.db'
$env:EGEVOLUTION_LOCAL_CHECK = '1'
$env:FLASK_DEBUG = '0'
& $pythonExe -B -m flask --app app run --host 127.0.0.1 --port 5000 --no-debugger --no-reload
```

Открыть `http://127.0.0.1:5000/variants`; завершить Ctrl+C. Обязательные
переменные авторизации по-прежнему читаются из имеющегося `.env`/окружения.
Не публиковать их значения. Экспортированный путь имеет приоритет над `.env`.
Локальные переменные оставить установленными на время работы; их удаление
вернёт следующий запуск к исходной базе.

Локальный режим отключает Telegram даже при наличии настроенного токена,
не создаёт поток отправки уведомления, не печатает созданный пароль.
Запись заданий, вариантов, теории, уроков и аватаров через HTTP заблокирована.
Ученические ответы и административные операции с БД относятся только к копии.
Не использовать локальный режим для проверки сохранения файлов конструктора.

Локальный CSP блокирует Метрику и другие внешние скрипты, запросы, шрифты,
картинки/медиа и отправку форм наружу. Поэтому внешние ресурсы могут не
отображаться; шрифт использует системный fallback. Явный переход пользователя
по внешней ссылке CSP не запрещает — для этой проверки оставаться на localhost.
Шаблоны и интерфейсы ради этого не меняются. Это режим разработчика, не
песочница для произвольного Python-кода или ручных служебных скриптов.

## Проверки без сервера

```powershell
& $pythonExe -B -X utf8 -m unittest discover -s tests -p test_local_database.py -v
```

Тесты сначала проверяют подключения статически, затем используют временную
копию Python-файлов и фиктивную БД; чтение `.env` и сетевые вызовы отключены.
Каждое подключение при импорте и HTTP-проверке обязано адресовать временную БД.
Проверяются абсолютные/относительные пути, отсутствие автоматического fallback,
отказ для оригинала/жёсткой ссылки, блокировка записи файлов и локальный CSP.
SHA-256 исходной `users.db` сравнивается до и после каждой проверки.
