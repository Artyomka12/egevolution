## Решения владельца

Предварительные правила из задания: active на пару ученик–тест; один writer с
явным claim после смены документа/устройства; квота расходуется при старте во всех
версиях; snapshot политики эталонов; пустой ответ=0; равный лучший процент — более
поздняя полностью проверенная попытка; компенсация сбоя отдельным grant.

Дополнительно подтверждено в диалоге:
- LF на вводе и в транспорте; чистая функция проверки не нормализует текст.
- Пропуск всегда остаётся 0; выставление 1 пропуску запрещено.
- Предложенные численные пределы количества/длины/времени пока не вводить.
- Pillow разрешён в отдельном локальном окружении с зависимостью проекта.

## Единые контракты и владение

Источник маршрутов/DTO — ТЗ §8; таблиц — §4. Новых альтернативных API нет.
Черновик: `title`, `description`, `time_limit_seconds`, `attempt_limit` (null —
без лимита), `show_correct_answers`, `questions`. Вопрос: `title`, `prompt_text`,
`code_text`, `question_type`, `free_input_mode`, `grading_mode`, `media_id`,
`options:[{text,is_correct}]`, `accepted_answers:[str]`. Published IDs выдаёт БД.

Repository: явный путь БД, `BEGIN IMMEDIATE`; функции `*_in_transaction`
не коммитят. Service проверяет права/replay/ревизии/дедлайн после write-lock.
Writer token: заголовок `X-Test-Writer-Token`, хранение только в памяти документа,
на сервере только hash. Start не захватывает writer; явный claim.
Ученический DTO формируется по allowlist. Эталоны только latest+graded+snapshot.
Summary: `earned,total,checked_count,pending_count,final_score,percentage,is_final`.
