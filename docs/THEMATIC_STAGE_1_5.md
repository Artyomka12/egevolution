вариантов. Данные берутся из SQLite и неизменяемых версий этапов 1.2–1.4.
Новая миграция не требуется. Прототипы и полноценные варианты не изменены.

## Маршруты

| Метод / маршрут | Назначение |
| --- | --- |
| GET `/variants` | Существующая страница; реальные тематические карточки, по умолчанию полноценные |
| GET `/variants?kind=thematic` | Та же страница с выбранной тематической вкладкой |
| GET `/api/thematic-variants` | Опубликованный каталог для текущего пользователя |
| GET `/thematic-variants/<id>/solve` | Страница решения; сам GET не создаёт попытку |
| GET `/thematic-attempts/<id>/result` | Завершённый результат владельца |
| GET `/api/thematic-attempts/<id>/result` | Завершённый результат владельца в JSON |
| GET `/admin/user/<user_id>/thematic-attempt/<id>` | Администратор: результат именно указанного ученика |
| GET `/stats`, `/admin/user/<user_id>` | Существующая история с записями обоих типов |

Страница решения использует существующие start, GET attempt, PUT answer, POST check,
POST submit и закрытые media-маршруты этапа 1.4. GET attempt теперь возвращает
`description_html` после серверной очистки разметки вместо сырого `description`.
Автоматической миграции или инициализации тематической схемы новые маршруты не выполняют.

## Поведение и безопасность

Каталог сортируется по ручному порядку преподавателя. Лучший результат — максимальное
число правильных задач, затем точная доля правильных задач, а не округлённый процент.
Карточка одновременно показывает лучший результат и активный прогресс; старая активная
версия сохраняет собственное число задач. Без активной попытки карточка пройденного
варианта ведёт к лучшему результату; новое прохождение запускается со страницы результата.

Браузер не проверяет правильность. Во время решения сервер выдаёт только условия,
форму ввода, материалы условия, собственные ответы, ревизии и результат проверки.
Эталоны выдаются отдельным представлением только после завершения. Персональные
страницы/API имеют no-store; новые страницы решения/результата не подключают аналитику.
Условия проходят HTML allowlist, ответы вставляются как текст, медиа выдаются через
проверку владельца и версии либо отдельный административный маршрут.

Автосохранение работает через последовательную очередь с задержкой 700 мс. Потерянный
ответ сервера повторяется с прежним ключом и телом. Новые изменения во время запроса
сохраняются следующим запросом. Конфликт не перезаписывает чужую ревизию; местный ввод
сохраняется на странице до явной сверки. Завершение сначала дожидается очереди, затем
передаёт все последние значения вместе с ревизиями в атомарном финальном пакете.
Сервер заново проверяет весь вариант. При конфликте попытка не завершается частично.

Показания времени обновляются по серверу раз в 10 секунд, между ответами отображается
локальное приближение. Итоговое время вычисляет только сервер с исключением скрытий.
После скрытия интерфейс блокируется; после восстановления публикации можно продолжить
исходную версию. Удаление завершает попытку на сервере; интерфейс направляет к результату.

Результаты и история сохраняются после редактирования, скрытия и удаления варианта.
Каждая завершённая попытка — отдельная запись. Тематические записи не участвуют в
`total_variants`, `best_score`, `average_score` ЕГЭ. Новая вкладка статистики не добавлялась.
Административный просмотр проверяет роль и принадлежность попытки указанному ученику.

Если ваш проверочный сервер уже работает на 5001, перезапуск для загрузки нового Python

$env:FLASK_DEBUG = '0'

1. Открыть `http://127.0.0.1:5001/variants`, проверить прежние 20 карточек и переключатель.
   На тестовой копии использовать собственный опубликованный тематический вариант;
   при отсутствии публикаций увидеть согласованное пустое состояние.
2. Пройти задачи со строкой, парой и таблицей ответов; проверить условия/код/изображения/
   вложения. Ввести ответ, дождаться «Сохранено», обновить страницу и продолжить ту же попытку.
3. Проверить ответ, изменить и проверить снова. В Network убедиться, что активный ответ API

4. Через DevTools временно включить Offline: ввести ответ, увидеть ошибку, восстановить сеть

   требует сверки и не перезаписывает ответ молча.
5. Ввести последний ответ и сразу завершить; проверить предупреждение о пропусках,
   сохранение последнего ввода, результат 0/1, процент, время и раскрываемые условия.
   Начать ещё раз: новая попытка, прежняя остаётся в истории.
6. При активной попытке скрыть вариант через отдельную административную сессию этой копии:

   Проверить одновременно лучший завершённый результат и активный прогресс.
7. Опубликовать новую версию: старая активная попытка и её результат сохраняют прежние
   условия. Удалить проверочный вариант с подтверждением: история и результат доступны,
   новое прохождение запрещено, активная попытка автоматически завершена.
8. В `/stats` и `/admin/user/ID` проверить общий список, соответствующие ссылки и неизменные

9. В Chrome проверить 360, 768, 1440 и 1920 px: каталог, решение, результат, длинный ввод,

## Ограничения

Доступный браузерный инструмент не обнаружил браузеров; визуальная проверка этих четырёх
ширин и полноценный браузерный сценарий ещё требуют ручного согласования. Серверные тесты
и тесты очереди не заменяют проверки DOM, прокрутки, фокуса и фактического отображения.
Адаптивные правила перенесены из утверждённых макетов с локальной прокруткой широких таблиц.

Несохранённый ввод при сетевом сбое хранится только в открытой странице; перед её закрытием
выводится стандартное предупреждение браузера. Закрытие вкладки вопреки предупреждению
или аварийное завершение браузера может потерять ещё не отправленные изменения.
История пока выводится целиком, без новой пагинации; большие объёмы потребуют отдельной
оценки производительности. Проверка на SQLite 3.26 не выполнялась: установлен движок 3.49.1,
новые запросы не требуют возможностей новее 3.26. Известных падений выполненных тестов нет.

Этапы раздела «Тесты», теория и следующие этапы тематических вариантов не начаты.
