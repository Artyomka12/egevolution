## Маршруты

| Метод и путь | Назначение |
| --- | --- |
| GET `/admin/thematic-variants` | Управление каталогом, порядок, скрытие/возврат |
| GET `/admin/thematic-variants/new` | Новый несохранённый черновик; GET ничего не создаёт |
| GET `/admin/thematic-variants/<id>/edit` | Отдельный конструктор |
| GET/POST `/api/admin/thematic-variants` | Каталог / создание черновика |
| GET/PUT `/api/admin/thematic-variants/<id>/draft` | Получение / сохранение черновика |
| POST `/api/admin/thematic-variants/<id>/publish` | Создание неизменяемой версии |
| PATCH `/api/admin/thematic-variants/<id>/visibility` | Скрыть / показать прежнюю действующую версию |
| PUT `/api/admin/thematic-variants/order` | Ручной порядок всего каталога |
| GET `/api/admin/thematic-bank/<number>` | Полные условия реального банка №1–27 |
| GET `/api/admin/thematic-bank/<number>/<id>/media/<role>/<position>` | Материал конкретной задачи банка |
| GET `/api/admin/thematic-variants/<id>/media/<media_id>` | Закрытая копия материала опубликованной версии |

Все маршруты проверяют актуальный `users.is_admin`; роль из cookie не используется.
CSRFProtect приложения защищает все изменяющие запросы. API возвращает 401/403, ошибки
валидации 400, конфликты ревизий 409, отсутствие схемы 503 `SCHEMA_REQUIRED`.
Нет административного удаления вариантов: завершение активных попыток при удалении
предусмотрено отдельно на этапе 1.4.

## Данные, транзакции и файлы

Черновик содержит название, описание, упорядоченные source-пары и хэши исходных задач.
Сервер загружает эталоны только из банка; поля grading/пути клиента не принимаются.
Повтор source-пары запрещён. Несколько разных задач одного номера ЕГЭ разрешены.
При изменении банка сохранение/публикация устаревшего выбора отклоняется; задачу нужно
удалить из черновика и заново добавить после просмотра актуального условия.

PUT черновика использует `expected_revision`. Публикация использует ревизии черновика
и варианта, `request_key` и хэш запроса. Повтор успешного create/publish с тем же ключом
возвращает прежний идентификатор, другой payload с тем же ключом даёт 409.
Ручной порядок использует ревизию каталога и полный список существующих идентификаторов.

До SQLite write-lock выполняются чтение и проверка материалов, копирование, SHA-256
и повторная проверка источников. В одном BEGIN IMMEDIATE создаются версия/items/media,
версия запечатывается, переключается указатель, обновляются ревизии, закрывается
интервал скрытия и записывается receipt. Ошибка откатывает весь набор DB-изменений.
Сохранение черновика не меняет действующую публикацию. Возврат скрытой публикации
через visibility не создаёт новую content-version.

Копии находятся в `data/thematic/media/`, вне static, исключены из Git. Папка создаётся
только при реальном копировании материала, а не при импорте приложения. На тестах путь
переопределяется в `THEMATIC_MEDIA_ROOT` на временный каталог. Публикация не переписывает
файлы банка. Имя копии — SHA-256 содержимого; запись сначала во временный файл с fsync,
затем атомарное переименование. Связи и подписи принадлежат версии.

Проверяются пути, существование, предел 64 МБ, сигнатуры форматов, размеры растров
(до 40 млн пикселей), структура и CRC PNG, структура заголовка JPEG, ZIP-контейнеры
офисных вложений. SVG/HTML не разрешены как изображения. Это не универсальный декодер
изображений и не антивирус. Новые загрузки в конструктор не добавлены. Материалы
берутся только из существующего локального банка; вложения отдаются как download,
ответы — с nosniff, no-store и CSP. HTML условий допускает только текстовые теги,
таблицы и код без исполняемых атрибутов. Код условий никогда не выполняется.

При неуспешной публикации могут остаться подготовленные файлы без DB-ссылок.
Автоматического удаления таких файлов нет: удаление исторического материала недопустимо.
Очистка после сверки всех ссылок и резервных копий — отдельная эксплуатационная задача.

## Как владельцу безопасно проверить локально

Ниже инструкция для отдельного разрешённого запуска владельцем, не выполненные агентом
команды. Не указывайте `users.db` или `.local-data/dev-users.db` как цель миграции.
Существующий сервер не нужно останавливать; проверочный экземпляр использует порт 5001.

1. Создать **третью** копию и её согласованный backup. Команда откажется перезаписывать
   уже существующие файлы. Источник открывается исключительно read-only через SQLite backup:

```powershell
$py = 'C:\Users\Артем\AppData\Local\Programs\Python\Python312\python.exe'
@'
from contextlib import closing
from pathlib import Path
import sqlite3
source = Path('.local-data/dev-users.db').resolve(strict=True)
target = Path('.local-data/thematic-stage13.db').resolve()
backup = Path('.local-data/thematic-stage13-before.db').resolve()
if target.exists() or backup.exists():
    raise SystemExit('Refusing to overwrite an existing test copy or backup')
with closing(sqlite3.connect(source.as_uri() + '?mode=ro', uri=True)) as src:
    with closing(sqlite3.connect(target)) as dst:
        src.backup(dst)
        assert dst.execute('PRAGMA integrity_check').fetchone()[0] == 'ok'
        assert not dst.execute('PRAGMA foreign_key_check').fetchall()
        with closing(sqlite3.connect(backup)) as bak:
            dst.backup(bak)
print('Separate copy and matching backup created')
'@ | & $py -B -X utf8 -
```

2. Аудит, затем явная миграция только новой, ещё не открытой сервером копии:

```powershell
& $py -B scripts/migrate.py --database .local-data/thematic-stage13.db
& $py -B scripts/migrate.py --database .local-data/thematic-stage13.db --apply --backup .local-data/thematic-stage13-before.db --confirm-offline
```

Если аудит сообщает о несогласованной истории, FK или checksum, остановиться, а не
удалять журнал/менять SQL миграции. Исходные DB и backup не исправлять автоматически.

3. В отдельном терминале VS Code, из корня проекта:

```powershell
$env:EGEVOLUTION_DB_PATH = (Resolve-Path '.local-data/thematic-stage13.db').Path
$env:EGEVOLUTION_LOCAL_CHECK = '1'
$env:FLASK_DEBUG = '0'
& 'C:\Users\Артем\AppData\Local\Programs\Python\Python312\python.exe' -B -m flask --app app run --host 127.0.0.1 --port 5001 --no-debugger --no-reload
```

Войти своей административной учётной записью на копии, открыть
`http://127.0.0.1:5001/admin/thematic-variants`. Секреты/пароли не вставлять в отчёт.
LOCAL_CHECK отключает реальные уведомления и прежние операции записи JSON-контента.
Новый конструктор пишет только в выбранную тестовую DB и закрытые копии media.

4. Проверить №1–27, разворачивание условий, изображения/таблицы/код/файлы; добавление
   двух разных задач одного номера, блокировку повтора, удаление и перестановку;
   save/reload, публикацию версии 1, сохранение её черновика без смены публикации,
   публикацию версии 2, скрытие/возврат и ручной порядок. В двух вкладках проверить
   конфликт устаревшего черновика. Проверить Chrome на 360/768/1440/1920 px.

Автоматизированная визуальная проверка не заменена серверными тестами: браузерный
инструмент в этой сессии не предоставил доступного браузера. Требуется визуальное
согласование владельца; CSS и адаптивные пороги перенесены из утверждённого макета.

## Откат локальной проверки

Не менять живые DB и не откатывать схему поверх результатов. Закрыть только собственный
проверочный экземпляр, сохранить его DB/media, затем при необходимости восстановить
отдельную копию из `thematic-stage13-before.db` под новым именем. Перед удалением media
проверить ссылки всех версий. Существующий сайт/конструктор и исходные JSON не затронуты.
