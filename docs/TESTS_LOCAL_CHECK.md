# Локальная проверка раздела «Тесты»

Все команды выполняются из корня проекта. Рабочие БД не мигрированы. Текущие
серверы не перезапускались. Для проверки создано отдельное окружение
`.local-data/tests-venv` с Pillow 12.3.0; глобальная установка не требуется.

## Автоматические проверки

```powershell
& '.local-data/tests-venv/Scripts/python.exe' -B -X utf8 scripts/check_tests_local.py
node --test tests/test_tests_save_queue.cjs tests/test_tests_admin_requests.cjs
```

Python runner очищает прикладное окружение, запрещает dotenv и исходящие сетевые
соединения. SQLite допускается только во временных fixtures; ссылки на три рабочие
БД отклоняются. `app.py` в интеграционных тестах импортируется только после установки
этих ограничений. Миграции применяются к фиктивным БД с собственным backup.

Старая функциональность проверяется тем же runner:

```powershell
& '.local-data/tests-venv/Scripts/python.exe' -B -X utf8 scripts/check_tests_local.py --pattern 'test_thematic_*.py'
& '.local-data/tests-venv/Scripts/python.exe' -B -X utf8 scripts/check_tests_local.py --pattern 'test_homepage_integration.py'
& '.local-data/tests-venv/Scripts/python.exe' -B -X utf8 scripts/check_tests_local.py --pattern 'test_bank_api_security.py'
& '.local-data/tests-venv/Scripts/python.exe' -B -X utf8 scripts/check_tests_local.py --pattern 'test_local_database.py'
```

## Новый фиктивный сайт

```powershell
& '.local-data/tests-venv/Scripts/python.exe' -B -X utf8 scripts/run_tests_local.py --worker-interval 1
```

Каждый запуск создаёт новую БД и private media во временном каталоге ОС. Адрес
`http://127.0.0.1:<свободный порт>` выводится в консоль. Это отдельный сервер;
существующие Flask-процессы не используются. Проверочные учётные записи:
`tests-admin`, `tests-student`, `tests-other`; общий фиктивный пароль —
`local-tests-only`. Каталог изначально пуст: преподаватель создаёт тест в `/admin/tests`.

Сценарий проверки: создать и опубликовать тест с тремя типами вопросов, пройти его
как ученик, проверить ручной ответ в очереди администратора, открыть вкладку «Тесты»
в `/admin/user/2`, посмотреть историю и выдать дополнительные попытки этому ученику.
Оценки бинарные, пропуск всегда 0. До завершения ручной проверки эталоны ученику
не выдаются; подробности доступны только для последней собственной попытки.

Интервал 1 секунда относится только к этой фиктивной проверке. Без параметра
`--worker-interval` сервер остаётся доступен для чтения и настройки, а новые попытки
запрещены. При остановке своего worker новые старты также закрываются. Ctrl+C
завершает только созданный здесь сервер и его worker. `--create-only` создаёт
фиктивную БД без запуска процессов. Production-расписание worker этим не утверждается.

## Браузерный сценарий

```powershell
node scripts/check_tests_browser.cjs
```

Требуется установленный Chrome либо Edge и Node с встроенным WebSocket (проверено
на Node 24). Новые зависимости не устанавливаются. Сценарий запускает собственный
фиктивный сайт, worker и headless-браузер с новым временным профилем. Он создаёт
тесты через HTTP, проверяет claim, ввод, autosave, отправку, скрытие эталонов,
оценивание, статистику и grants. Существующие браузерные профили не используются.

Снимки при ширинах 360/768/1440/1920, JSON-отчёт и журнал фиктивного сайта сохраняются
в новом `%TEMP%/ege-tests-browser-*`. Путь выводится в конце. Сервер и worker завершаются
через закрытие stdin; браузер — через его собственное CDP-соединение. Рабочие данные
в артефакты этого сценария не попадают.

## Границы готовности

Итоговые результаты и отложенные компоненты записаны в
`docs/TESTS_IMPLEMENTATION_STATUS.md`. Запуск на SQLite 3.26.0 пока не проверен;
фактический локальный движок — 3.49.1. Физическая уборка media без ссылок и удаление
аккаунтов, связанных с тестами, отложены после отказа автоматической проверки разрешений.
Удаление такого аккаунта возвращает 409 и сохраняет данные. Подтверждённое удаление
самого теста реализовано и проверено на фиктивных данных.

Эти команды не являются процедурой production-выпуска. Рабочие БД, REG.RU,
существующие варианты, прототипы и действующие серверы остаются вне локального прогона.
